# Cron CPU 時間の検証（更新: 件数スキップ + 1 人振り分け）

## Cloudflare の上限

| プラン | 呼び出し | CPU time |
| --- | --- | --- |
| Free | Cron 1 回 | **10 ms** |
| Free | HTTP 1 回 | **10 ms** |
| Paid | Cron（間隔 ≥ 1 時間） | 最大 15 分 |
| Paid | HTTP | 既定 30 秒（最大 5 分） |

`fetch` / KV の待ちは CPU に含まれない。

## 設計上の答え

### 1 人ごとに別 Cron は？

**動的にはできない。** Cron 式は `wrangler` に静的定義する。Free はアカウントあたり **5 本**まで。
代わりに **Cron 1 本 → 購読ごとに別 HTTP**（`/api/notify/cron-tick`）へ振り分け、
**1 人 = 1 呼び出し = 別 CPU 枠**にする。

### 件数不変時のパース省略

未読件数が前回と同じ／減っているときは通知一覧 HTML を取らずパースしない。
トレードオフ: 「既読 1 + 新着 1」で件数が同じだと、次に件数が増えるまで Discord に出ない。
